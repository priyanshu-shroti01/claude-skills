# Research Intelligence

Input: a project brief. Output: the research packet the whole team builds
from. Run by research-agent (with competitor-agent for the matrix).

## Packet sections (all required; "none found" is a valid, stated result)

1. **Competitor list** — 3–6 direct + 2–3 aspirational/adjacent; one line
   each on why they're in the set.
2. **Design references** — specific pages/patterns worth studying (with
   URLs + what precisely is instructive); adjacent categories encouraged.
3. **UX patterns** — how this category handles its core flows: nav
   models, conversion paths, onboarding, pricing presentation; which
   patterns are table stakes vs. differentiators.
4. **Content patterns** — information users expect, tone norms, content
   depth that wins, FAQ/objection themes.
5. **SEO opportunities** — query themes, apparent gaps, SERP features in
   play, GEO/AI-answer presence of competitors.
6. **Technology patterns** — what the category ships (stacks, perf
   characteristics measured where possible), constraints worth knowing.
7. **Visual direction (recommended)** — 2–3 distinct, defensible
   directions with rationale tied to audience + differentiation; feeds
   design-direction.
8. **Differentiation opportunities** — where the category is uniformly
   weak or identical, and how this project exploits it.
9. **Risks** — market, technical, content, legal/ToS observations;
   anything that could invalidate the plan.

## Method rules

- Official docs > analyst posts > tutorials. Every claim: source + date.
- Fact / inference / opinion labeled throughout.
- **Extraction, not copying**: record the pattern (problem → solution →
  why it works → failure modes), never mirror a competitor's execution.
- Measure where cheap: a Lighthouse run on three competitors beats an
  adjective.
- Timebox per section; a packet a week late feeds nothing.

## Handoffs

product-director (scope), design-director (direction), seo-agent
(opportunity detail), growth-agent (baseline), memory (durable market
facts, dated).
